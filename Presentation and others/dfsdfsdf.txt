================================================================================
                         SENTINELAI: FRAMEWORKS, TOOLS &
                          A-TO-Z ARCHITECTURE DETAILS
================================================================================

This document provides a comprehensive list of all frameworks, libraries, APIs, and 
tools utilized in the SentinelAI project, followed by a complete end-to-end (A to Z) 
technical explanation of how the application functions.

--------------------------------------------------------------------------------
PART 1: FRAMEWORKS, LIBRARIES, AND TOOLS USED
--------------------------------------------------------------------------------

A. Machine Learning & Dataset Generation (Python Environment)
   1. Python 3.x: The core programming language used to build the training pipeline.
   2. TensorFlow / Keras (v2.16+): Used for building, compiling, training, and 
      evaluating the 1D Convolutional Neural Network (CNN). Also utilized to export 
      the trained Keras model into the TensorFlow Lite format (.tflite).
   3. Librosa: An audio and music processing library used to load WAV/MP3 files, 
      resample audio signals to 16,000 Hz, and perform data augmentation (specifically 
      pitch-shifting using librosa.effects.pitch_shift).
   4. gTTS (Google Text-to-Speech): Used to programmatically generate clean synthetic 
      voices speaking conversational bank scam scripts.
   5. NumPy: Used for efficient mathematical operations on multi-dimensional arrays, 
      including audio amplitude normalization, adding Gaussian noise to waveforms, 
      shuffling datasets, and adjusting dimensions.
   6. SoundFile: A library to write processed NumPy arrays back into physical WAV files.
   7. Glob & OS: Core Python modules used to search directories, manage paths, and 
      create training directories.

B. Android Application Architecture
   1. Kotlin & JVM: The language and runtime platform used to write the Android app, 
      configured with JVM Toolchain v17.
   2. Gradle (Kotlin DSL): Used to orchestrate the build process and handle 
      dependencies. Uses Android Gradle Plugin (AGP) version 9.0.1 and Kotlin 
      plugin version 2.3.20.
   3. Jetpack Compose (BOM 2026.03.01): The modern UI toolkit used to build the entire 
      reactive, dark-mode user interface. Specific components include:
      - androidx.compose.ui
      - androidx.compose.material3 (Material Design 3 components)
      - androidx.activity.compose (Integration between Compose and Activity)
   4. Android Lifecycle Components (v2.10.0):
      - lifecycle-runtime-compose & lifecycle-viewmodel-compose (To collect states 
        in a lifecycle-aware manner).
   5. Navigation 3 (v1.0.1): Modern Jetpack navigation framework (`navigation3-ui` 
      and `navigation3-runtime`).
   6. TensorFlow Lite Android Support:
      - `org.tensorflow:tensorflow-lite:2.16.1`: The primary runtime engine used for 
        on-device machine learning inference.
      - `org.tensorflow:tensorflow-lite-select-tf-ops:2.16.1`: Included to support 
        complex select TensorFlow operators during TFLite execution.
   7. Android Audio APIs:
      - `AudioRecord`: Captures low-latency, raw 16-bit PCM mono audio buffers directly 
        from the physical microphone (`MediaRecorder.AudioSource.MIC`) at 16,000 Hz.
   8. Kotlin Coroutines (v1.10.2): Used to perform heavy operations in the background 
      without blocking the main thread, such as streaming audio samples, performing 
      VAD, running TFLite inference, and running simulations.


--------------------------------------------------------------------------------
PART 2: THE A-TO-Z ARCHITECTURE AND FUNCTIONAL FLOW
--------------------------------------------------------------------------------

The application runs in two distinct phases: 
- Phase 1: Offline Training (Python script workflow generating the .tflite model)
- Phase 2: Online Inference & Live Monitoring (Android app running on-device)

Below is the step-by-step lifecycle of the entire application.

================================================================================
PHASE 1: OFFLINE MODEL DEVELOPMENT (A TO E)
================================================================================

[Step A] Dataset Generation & Voice Augmentation (download_sample_data.py)
   1. The script initializes directories `dataset/real` and `dataset/fake`.
   2. Generating Fake/Synthetic Samples:
      - 15 scam-related phrases (e.g., "Your account has been compromised, please 
        provide your details.") are compiled.
      - gTTS sends these phrases to Google's TTS API, returning MP3 voice files.
      - Librosa loads the MP3s, automatically resampling them to 16,000 Hz.
      - The resulting waveforms are written as standard 16kHz WAV files under `dataset/fake/`.
   3. Generating Real Samples:
      - A sample of human speech is downloaded from a public repository.
      - To create a diverse set of 15 unique "real" voices, the script applies pitch 
        shifting: it shifts the pitch of the source recording by a random number 
        of semitones between -4.0 and +4.0.
      - These shifted waveforms are saved as 16kHz WAV files under `dataset/real/`.

[Step B] Audio Preprocessing (train_model.py)
   1. Resampling and Chunking:
      - All audio files are loaded at 16kHz.
      - The signals are divided into exact 1-second chunks (16,000 samples).
      - If a file is shorter than 1 second, it is padded with trailing zeros to reach 
        exactly 16,000 samples.
   2. Amplitude Normalization:
      - To ensure the model learns spectral/temporal voice properties rather than 
        volume variations, each chunk is divided by its maximum absolute amplitude:
        `chunk = chunk / max(abs(chunk))` (if maximum amplitude > 0.001).
   3. Gaussian Noise Augmentation:
      - Random Gaussian noise (mean=0, standard deviation=0.015) is generated and added 
        to all audio chunks. This simulates microphone static and channel distortion.
      - The clean chunks and noisy chunks are concatenated together, doubling the 
        dataset size for robust generalization.
   4. Reshaping:
      - Inputs are reshaped to `(samples, 16000, 1)` and labels are created (0.0 for 
        real speech, 1.0 for synthetic/fake speech).
      - The dataset is shuffled randomly.

[Step C] 1D Convolutional Neural Network (CNN) Architecture
   The network processes raw 1D waveforms directly rather than computing 2D spectrograms:
   1. Input Layer: Accept raw vector of dimension `(16000, 1)`.
   2. Convolutional Block 1:
      - Conv1D: 32 filters, large kernel size of 64, stride of 8 (coarse feature extractor).
      - Batch Normalization & ReLU activation.
      - MaxPooling1D: pool size 4.
      - Dropout: 20% to prevent overfitting.
   3. Convolutional Block 2:
      - Conv1D: 64 filters, kernel size of 32, stride of 4.
      - Batch Normalization & ReLU activation.
      - MaxPooling1D: pool size 4.
      - Dropout: 20%.
   4. Convolutional Block 3:
      - Conv1D: 128 filters, kernel size of 16, stride of 2.
      - Batch Normalization & ReLU activation.
      - MaxPooling1D: pool size 2.
      - Dropout: 20%.
   5. Classification Dense Block:
      - Flatten layer converts 3D tensors to 1D vectors.
      - Dense Layer: 64 units, ReLU activation.
      - Dropout: 30%.
      - Output Layer: Dense layer, 1 unit, Sigmoid activation (outputs float between 
        0.0 [Real] and 1.0 [Synthetic/Spoofed]).

[Step D] Model Training
   1. The model compiles using the Adam optimizer (learning rate = 0.001) and 
      binary crossentropy loss.
   2. The dataset is trained for 20 epochs with a batch size of 8 and a 20% validation split.

[Step E] TFLite Conversion & Asset Integration
   1. The Keras model is converted into the TensorFlow Lite format (.tflite).
   2. Crucially, no quantization is used. This prevents weight/activation distortions that 
      can trigger runtime incompatibility (e.g., FULLY_CONNECTED operations v12 issues) 
      on various Android systems.
   3. The generated file `voice_spoof_detector.tflite` (~1.02 MB) is copied into the 
      Android project assets at: `SentinelAI/app/src/main/assets/models/voice_spoof_detector.tflite`.


================================================================================
PHASE 2: ONLINE REAL-TIME INFERENCE ON ANDROID (F TO L)
================================================================================

[Step F] Audio Acquisition (AudioRecordManager.kt)
   1. Initialization:
      - Configures Android's `AudioRecord` API to open a stream at 16,000 Hz, mono, 
        using 16-bit PCM encoding.
      - Calculates the minimum hardware buffer size. If recording fails to initialize 
        (e.g., due to simulator limitations or missing hardware), it automatically 
        delegates to a simulated fallback generator.
   2. Coroutine Stream Capture:
      - When monitoring starts, a coroutine is spawned on `Dispatchers.IO`.
      - It reads incoming audio into a `ShortArray` buffer of size 1024 samples.
      - Calculates Root Mean Square (RMS) energy: `rms = sqrt(sum(sample^2) / buffer_size)`.
        This is dispatched to the UI for the live amplitude progress bar.
      - Converts each 16-bit short sample to a normalized float: `float_val = short_val / 32767.0`.
   3. Rolling 1-Second Window:
      - The normalized floats are written to a rolling `floatBuffer` of size 16,000.
      - Once the buffer is full (exactly 16,000 samples/1 second of audio), the 
        manager clones the buffer, passes it to the `onBufferReady` callback, resets 
        its index, and continues writing new samples.

[Step G] Voice Activity Detection (VAD) & On-Device Processing (MainActivity.kt)
   1. The raw 16,000 floats are received in `MainActivity`.
   2. VAD Filter:
      - The RMS energy is computed.
      - If RMS is < 0.01 (silence, light breathing, or ambient room hum), the app 
        immediately skips running TFLite inference. It sets the spoofing probability 
        to 0.0 and latency to 1ms.
      - This bypass prevents the model from generating random false-positive scores 
        on background noise or silence.
   3. Amplitude Normalization:
      - If VAD is successful, the 16,000 samples are normalized by dividing by the 
        maximum absolute amplitude found in that specific 1-second chunk.
      - This aligns the live input's distribution exactly with the normalized 
        waveform training dataset.

[Step H] Local Machine Learning Inference (VoiceSpoofDetector.kt)
   1. Memory Mapping:
      - At startup, the app loads `voice_spoof_detector.tflite` from assets using 
        `FileChannel.map` to load it as a `MappedByteBuffer` for zero-copy memory efficiency.
      - Instantiates the TensorFlow Lite `Interpreter` with 2 execution threads.
   2. Input/Output Buffer Operations:
      - Direct native ByteBuffers are allocated for inputs (`16000 * 4 = 64,000` bytes) 
        and outputs (`1 * 4 = 4` bytes) using native byte ordering.
      - The normalized 16,000 float samples are copied into the input ByteBuffer.
   3. Running Inference:
      - Tracks start time using `System.nanoTime()`.
      - Invokes `interpreter.run(inputBuffer, outputBuffer)`.
      - Computes inference latency in milliseconds: `latency = (end - start) / 1,000,000`.
      - Extracts the output probability value from the output ByteBuffer (representing 
        the probability that the voice is synthetic, from 0.0 to 1.0).

[Step I] Temporal Probability Smoothing (MainActivity.kt)
   1. Due to brief gaps in speech or audio frames, single-frame predictions can spike.
   2. The activity maintains a rolling history (`voiceProbabilityHistory`) of the last 
      5 inference results (representing a rolling 5-second context window).
   3. The raw probabilities are smoothed using a simple rolling average:
      `smoothedProbability = sum(last_5_probs) / 5`.

[Step J] Live Transcript NLP Analysis (ConversationAnalyzer.kt)
   1. The app captures conversational transcripts (which can be simulated via the UI 
      using a realistic bank fraud sequence).
   2. Trigger Keywords Scans:
      The transcript is mapped against 4 intent categories:
      - `financial_request` (keywords: "send money", "wire transfer", "gift card", etc.)
      - `artificial_urgency` (keywords: "immediately", "right now", "arrest", "urgent", etc.)
      - `impersonation` (keywords: "this is your bank", "irs", "fbi", "police department", etc.)
      - `otp_request` (keywords: "one time passcode", "verification code", "otp", etc.)
   3. Scam Scoring:
      - 3 or more matched intents -> Scam Score = 0.95 (95% scam indicator).
      - 2 matched intents -> Scam Score = 0.70 (70% scam indicator).
      - 1 matched intent -> Scam Score = 0.40 (40% scam indicator).
      - 0 matched intents -> Scam Score = 0.10 (10% baseline).

[Step K] Composite Risk Calculation (RiskEngine.kt)
   1. The smoothed voice spoofing probability and the NLP conversation scam score are 
      passed to the `RiskEngine`.
   2. Max-Signal Principle:
      Instead of using a weighted average that might dilute critical threats (e.g., an 
      extremely obvious scam transcript spoken by a real human, or a clone voice speaking 
      normally), the engine takes the maximum of the two inputs:
      `combinedScore = max(voiceSyntheticProbability, conversationScamScore)`.
   3. Score Mapping:
      - `finalScore = combinedScore * 100` (coerced between 0 and 100).
      - Maps score to five severity levels:
        - SAFE: Score < 20
        - LOW: Score 20 to 39
        - MEDIUM: Score 40 to 59
        - HIGH: Score 60 to 79
        - CRITICAL: Score >= 80
   4. Signal Compilation:
      - If voice spoof probability > 0.5, adds "Possible AI-generated voice detected (X%)".
      - If conversation scam score > 0.5, adds "Suspicious conversation patterns detected".
      - appends all matching intent tags (e.g. `financial_request`, `artificial_urgency`).

[Step L] UI Reactive Render (HomeScreen.kt)
   1. The Jetpack Compose UI listens to changes in the activity states (recording state, 
      RMS amplitude, inference latency, model size, and RiskResult).
   2. Re-composes the UI in real time:
      - The Mic progress bar updates with live RMS amplitude changes.
      - The Edge AI Status Panel displays the current model stats and latency.
      - The scam risk card changes colors (Green, Yellow, Orange, Red, Crimson) and 
        displays the numerical score and bullet-pointed threat reasons.
      - Toggling the simulated scam script inputs updates the NLP transcript step-by-step, 
        escalating the risk level dynamically.
   3. Destruction: When the app is closed, `onDestroy()` releases the `AudioRecord` 
      stream resources and closes the TFLite interpreter to prevent memory leaks.
